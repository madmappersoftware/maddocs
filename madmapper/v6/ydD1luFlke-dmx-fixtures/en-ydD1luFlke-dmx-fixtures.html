DMX Filtering

DMX Filtering controls how MadMapper samples the video content for your lighting fixtures. Applying a filter averages the surrounding pixels, which helps prevent harsh flickering when playing high-contrast video over low-resolution LEDs.

  • None: Samples a single, exact pixel at the center of the fixture.
  • Box: Averages a square grid of pixels around the sample point (defined by the Size parameter).
  • Anamorphic: Averages an area with independent width and height parameters (X and Y), which is perfect for mapping rectangular LED strips or non-square pixels.

DMX Fixture Definitions

A DMX Fixture Definition describes the channel layout of a DMX lighting device so MadMapper knows how to control it. MadMapper ships with a built-in library of common fixtures (generic RGB pixels, RGBW strips, etc.), but you can create custom definitions for any DMX device — moving heads, laser fixtures, LED bars, fog machines, or complex multi-channel fixtures like the Minuit Une IVL Dice.

Fixture definitions are stored as .mmfl files (MadMapper Fixture Library). These files can be imported, exported, and shared between projects and users.

 

Opening the Editor

  1. Go to the DMX Fixtures tab (Cmd+4 / Ctrl+4)
  2. Click DMX + to create a new fixture
  3. In the fixture's properties, click Edit next to Fixture Library

This opens the Fixture Editor panel, which lists all available fixture definitions — both built-in and custom.

Keyboard shortcut to open the Fixture Editor panel directly: Option+Cmd+F (Mac) / Alt+Ctrl+F (Windows)

Creating a New Fixture

  1. In the Fixture Editor, click the + button
  2. Set the fixture name and group (used for organization in the library)
  3. Define the pixel grid dimensions (Width × Height) — use 1×1 for non-pixel fixtures
  4. Set the Pixel Type to Custom for non-standard channel layouts
  5. Add channels in order, specifying each channel's type, label, and bit depth

LED Array Configuration & Properties

When creating or editing a fixture in the Fixture Editor, the Properties panel provides the following options for arrays and matrices:

 

Size Mode

Option Description
Fixed Size Manually set the pixel grid dimensions (Width × Height)
LED Strip Mode Configure as a linear strip of pixels
Matrix Mode Configure as a 2D pixel grid

Mapping Modes

  • Fixed Size: Manually set the pixel grid dimensions (Width × Height). In this mode, you can customize the individual pixel patch by clicking directly on any pixel in the Pixel Mapping interface to toggle it between its DMX address and UNPATCHED.

  • LED Strip Mode: Configure the fixture as a linear strip. Once selected, you can adjust the specific number of LED pixels directly in the Fixture Inspector panel.

  • Matrix Mode: Configure the fixture as a 2D pixel grid. Similar to LED Strip Mode, you can adjust the number of matrix divisions in the Fixture Inspector to match your physical hardware.

 

Fixture Properties & Mapping

The Properties panel allows you to define the geometric structure of your fixture, while the Pixel Mapping interface gives you granular control over individual pixel addressing.

 

Pixel Type — Select the color model for the fixture's pixels: RGB, RGBW, or Custom (for non-standard channel layouts like the IVL Dice).

Pixel Size — The number of DMX channels per pixel (e.g., 3 for RGB, 4 for RGBW). Check Advanced to access per-channel type and label configuration.

Assignation — Defines the pixel scanning/addressing order for LED strips and matrices. The 16 arrow pattern icons represent different ways pixels can be wired through the grid: left-to-right then top-to-bottom (Z-pattern), serpentine/zigzag, bottom-to-top, column-first, and their mirrored and reversed variants. Select the pattern that matches how your LEDs are physically wired. Click Clear to reset.

Skip channels 511–512 — When enabled, MadMapper will leave DMX channels 511 and 512 empty at the end of each universe. Some DMX devices reserve these channels, and enabling this avoids addressing conflicts at universe boundaries.

Channel Types

Each channel in a fixture definition has a type that tells MadMapper how to interpret it:

Type Description Typical Use
R Red RGB/RGBW color mixing
G Green RGB/RGBW color mixing
B Blue RGB/RGBW color mixing
W White RGBW fixtures
L Luminance Single-channel brightness
C Cyan CMY color mixing
M Magenta CMY color mixing
Y Yellow CMY color mixing
Slider Generic DMX value (0–255) Dimmer, pan, tilt, speed, gobo, or any non-color channel with manual control
Expression GLSL expression Computed channel value driven by a formula (see Expression Channels below)
Unused Empty/skipped channel Placeholder for reserved or unneeded channels in the fixture's DMX footprint

Bit Depth

Channels can be set to 8 Bits (single channel, 0–255) or 16 Bits (two channels, coarse + fine, 0–65535). 

 

Expression Channels

Expression channels let you compute a DMX value using a GLSL expression instead of a fixed slider or color input. This is useful for deriving channel values from other parameters — for example, calculating a checksum, inverting a value, or mixing multiple inputs mathematically.

 

The following variables are available inside an expression:

Variable Description
R, G, B Current red, green, and blue color values
L Luminance value
W White value
C, M, Y Cyan, magenta, and yellow values
INDEX The pixel index within the fixture
posX, posY Normalized pixel position within the fixture grid
COMP Component index
time Current time value
Slider names The values of any Slider channels, referenced by their label name

Expressions follow GLSL syntax, so standard math functions like sin(), clamp(), mix(), step(), etc. are available.

Importing and Exporting

Import a Fixture Definition

  1. Open the Fixture Editor (click Edit next to Fixture Library on any fixture, or use Option+Cmd+F / Alt+Ctrl+F)
  2. Click Import...
  3. Select a .mmfl file
  4. The fixture appears in the library and is ready to assign

Export a Fixture Definition

  1. Open the Fixture Editor
  2. Select the fixture you want to export
  3. Click Export...
  4. Save the .mmfl file to share or back up

 

Quick links in the Fixture Editor Toolbar:

 

Exported .mmfl files can be shared with other MadMapper users, committed to a Git repository, or included with a project archive.

Import Fixtures from CSV

For large installations with many fixtures, MadMapper supports CSV import to batch-create fixtures with names, groups, and DMX addresses. Since MadMapper 5.2, the CSV can include group hierarchy using / notation (e.g., "Stage Fixtures/Fixture 1"). See File > Import DMX Fixtures from CSV for details.

Import Fixtures from SVG

For spatial layouts, MadMapper can import fixture positions from SVG files created in Illustrator or similar tools. This is especially useful for complex LED installations where fixture placement and DMX patching need to match a physical design precisely.

 

Learn more about here: DMX Import / Export from SVG 

Tips for Custom Fixtures

Naming conventions — Use clear, descriptive channel labels. Include "Fine" in the label for the LSB channel of 16-bit pairs so operators can quickly identify coarse/fine relationships.

Modes — Many fixtures have multiple DMX modes with different channel counts. Create a separate definition for each mode and include the mode in the product name (e.g., "Minuit Une IVL Dice Mode 1").

Testing — After creating a fixture definition, use the DMX Monitor panel (Option+Cmd+M / Alt+Ctrl+M) to verify that channels are mapping correctly and values are reaching the expected DMX addresses.

Color channel types — Use the correct R/G/B/W/C/M/Y types for color channels rather than Slider. This allows MadMapper's color engine to properly drive them with pixel-mapped media, materials, and color pickers.

Cross-universe fixtures — If your fixture spans more than 512 channels or if its DMX address places it near the end of a universe, enable avoidCrossUniversePixels to prevent a single pixel's channels from being split across two universes.

Backup — Keep your custom .mmfl files in a shared location or version control. Fixture definitions are stored within MadMapper's library, but having external backups ensures you can quickly rebuild on a new machine.
