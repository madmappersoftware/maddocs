Optimized Video Codecs

Selecting the appropriate video codec is a critical factor for the performance and stability of MadMapper projects. Projection mapping frequently requires playing multiple high-resolution video streams simultaneously, which can impact system resources if unoptimized formats are used.

While MadMapper utilizes native video engines (like AVFoundation on macOS and FFmpeg) to leverage hardware decoding whenever possible, the codec you choose determines how efficiently your system can process the media.

Recommended Codecs

HAP Codec

HAP is the industry-standard codec for live performance and multi-layer projection mapping.

  • How it works: It performs video decompression on the GPU rather than the CPU.

  • The Benefit: This enables the playback of multiple high-resolution video layers with minimal risk of dropped frames. It is well-suited for rapid triggering, reverse playback, and timeline scrubbing.

  • The Trade-off: The primary trade-off is that HAP files require high data rates and result in large file sizes.

  • Formats include: HAP (Standard), HAP Alpha (supports transparency), HAP Q (higher image quality), and HAP R (optimized for content requiring both high quality and alpha channels).

More info at: https://hap.video/

Apple ProRes

ProRes is a high-quality alternative, particularly optimized for macOS. Modern Apple Silicon Macs include dedicated media engines designed to decode ProRes efficiently.

  • The Benefit: It offers visually lossless quality with smaller file sizes than HAP.

  • The Trade-off: While efficient on Macs, it generally requires more system resources than HAP when playing a high number of simultaneous layers, especially on older hardware or Windows systems.

Codecs to Avoid for Live Performance

H.264 and H.265 (HEVC)

While H.264 and H.265 are common formats for web delivery and consumer devices, they are generally not recommended for live projection mapping.

  • The Problem: These are typically "inter-frame" codecs; they store keyframes and calculate the mathematical differences between them rather than storing every individual frame.

  • The Result: The CPU requires significant processing power to decode the video in real-time. Playing multiple clips simultaneously, reversing playback, or scrubbing the timeline can lead to dropped frames and reduced system responsiveness.

  • The Workaround: If you must use H.264 for non-linear playback or rapid triggering, you should configure your export settings to generate a keyframe for every single frame (often referred to as an "All-Intra" setting or a Keyframe Distance of 1). By ensuring each frame is a full image, you remove the heavy mathematical calculations required for inter-frame decoding. This will result in a larger overall file size, but it can significantly reduce CPU performance bottlenecks.

Performance Considerations: Storage Speed

Because optimized codecs like HAP use less CPU compression, their file sizes are significantly larger. This shifts the performance requirement from the processor to the storage drive.

To utilize these codecs effectively, media should be played from a fast Solid State Drive (SSD).

  • Standard HDDs: Traditional Hard Disk Drives (HDDs) often lack the read speeds required to supply high-bandwidth video formats to the GPU, which can result in stuttering playback.

  • NVMe SSDs: For optimal performance, use an internal NVMe SSD or a high-speed external Thunderbolt/USB-C SSD with high read/write capabilities to ensure smooth multi-stream playback.

Video Engines: macOS vs. Windows

MadMapper utilizes different underlying video frameworks depending on your operating system to ensure optimal playback performance. Here is an objective breakdown of the video engines available for macOS and Windows.

macOS Video Engines

  • AVFoundation: This is Apple's native multimedia framework and the recommended default engine for Mac users. It provides hardware-accelerated playback for standard formats and native, highly efficient decoding for Apple formats such as ProRes.

  • FFmpeg: Available as an alternative engine, FFmpeg provides broad compatibility for a wide variety of video containers and legacy codecs that AVFoundation may not natively support.

Windows (PC) Video Engines

  • Media Foundation: This is Microsoft's native multimedia framework for Windows. It provides hardware-accelerated decoding for standard formats (such as H.264 and HEVC) directly through the Windows operating system.

  • FFmpeg: On Windows, FFmpeg is utilized to ensure broad compatibility across the diverse range of video formats, containers, and codecs that exist outside of standard native Windows support.

Cross-Platform Hardware Decoding

Regardless of the operating system, MadMapper defaults to utilizing Hardware Decoders whenever supported by your specific media and hardware configuration.

This process routes video frame decoding directly to the GPU (Graphics Processing Unit) rather than the CPU. Hardware decoding reduces the processor load, freeing up system resources to maintain a stable frame rate for timeline playback, visual effects, and UI interactions.
